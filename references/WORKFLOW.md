# От исходника до готового Reels

Перед каждым новым видео прочитать активный STYLE_PROFILE.md и STYLE_CHANGELOG.md, если они есть. Описанные ниже визуальные параметры — стартовый стиль; принятые изменения ученика применяются по STYLE_ADAPTATION.md. Технические проверки и работа со смыслом сохраняются.

## Сохранность и смысл

Работать с копией исходника. Импорт создаёт новую папку public/projects/Video-… и отдельную композицию. До изменений сохранять версию. Для повторной сборки прочитать edit-map.json и проверить SHA-256 файла; одинаковое имя не доказывает одинаковый исходник.

Сначала прочитать всю транскрипцию. Для каждого повторного захода записать исходный интервал, законченность, уникальную мысль, выбран/отклонён и причину. Лишние слова, неудачные старты и паузы убирать с сохранением смысла. Не сохранять число из отвергнутого дубля в графике. Неоднозначный выбор оставить до уточнения.

Коррекции слов писать в копию words-original.json, а не менять только субтитр в TSX. keep.json — список сохраняемых исходных интервалов в секундах. Пересборка с --keep/--transcript всегда создаёт отдельную версию. После новой нарезки пересчитать все таймкоды сцен и звуков.

Для явных смысловых пар задавайте `captionGroupEnd: true` последнему слову каждого субтитра и `false` остальным словам в reviewed transcript. Если поле встречается хотя бы раз, импорт использует ручные границы групп. Проверить все группы и их длину перед рендером.

## Команды

Из папки созданного проекта (Windows: .venv\\Scripts\\python.exe вместо .venv/bin/python):

```bash
python scripts/setup.py --check
python scripts/setup.py
.venv/bin/python scripts/import-video.py /path/to/source.mp4
```

Из вывода READY взять ID и открыть public/projects/ID/review.json, words-original.json, captions.json, edit-map.json. Базовый импорт не является законченной смысловой режиссурой.

Создать SCENE_PLAN.md: фраза, её исходные/итоговые секунды, вывод для зрителя, предмет, действие, результат, развитие во времени, layout, материалы и ограничения. Выбрать компактные связанные сцены, оставляя лицо там, где оно объясняет лучше.

Сцены — компоненты с именем PascalCase, по файлу в src/local/scenes. Используйте SceneCanvas/Paper/appear из src/student-style.tsx, latestRef из tokens.ts и Lucide для действий. Типографика — редактируемая. Процесс должен меняться по глаголам речи: ввод→нажатие→ответ, документ→редактура→результат. На каждом этапе проверить читаемость. Пример структуры scenes.json (тайминги заменить своими):

```json
[
  {"start": 5.0, "end": 10.0, "component": "MyProcess", "layout": "split"},
  {"start": 10.0, "end": 14.0, "component": "MyResult", "layout": "full"}
]
```

В editing-profile.json задать hookTitle, hookAccent и при необходимости hookKicker под этот сценарий. Если заголовок не нужен — hookTitle пустой. Шрифт/положение/тень и layout поддержаны учебным генератором, а не оставлены только словесной инструкцией.

```bash
.venv/bin/python scripts/import-video.py /path/to/source.mp4 --transcript words-reviewed.json --keep keep.json --scenes scenes.json
```

После ручного изменения JSX не перезапускать импорт поверх него: следующая версия отдельная. Для каждого клипа оставить отдельный Interactive-узел; Prettier разносит узлы по строкам. Root/Registry подключают новую композицию.

## Музыка и звук

Сначала проверить голос и пики. Исходный processVoice=false. Изменять голос только после оценки проблемы; не переносить усиление эталона механически. При необходимости выбирать gain с запасом пиков и записывать его в REVIEW.md.

В комплекте есть разрешённый instrumental public/music/the-child.mp3. Можно выбрать другой трек, подходящий смыслу. Для подготовки:

```bash
.venv/bin/python scripts/prepare-music-bed.py --music public/music/the-child.mp3 --voice public/projects/ID/voice-edited.wav --gap-db 16 --duck-ratio 2.5 --fade-in 0.6 --fade-out 1.2 --out public/projects/ID/music-prepared.wav --preview-out out/music-preview.wav
```

--voice-gain-db должен соответствовать действительному усилению голоса в JSX; по умолчанию 0. Для трека короче видео требуется другой фрагмент или явно выбранная петля; скрипт не зацикливает его молча. Готовый music-prepared.wav содержит только музыку. Подключить отдельным Audio volume={1} на длительность ролика. preview.wav — контрольный микс, его не подключать вместе с тем же голосом.

Короткие soft-tick/soft-move — только на смысловых действиях, на тихом уровне относительно речи. Прослушать границы, входы/выходы, концевая согласная и последний стык. Если в среде нет аудиовосприятия, измерить звук и честно пометить слуховую проверку как pending; запросить у студента её выполнение.

## Проверка и выдача

```bash
npx tsc --noEmit
.venv/bin/python scripts/check-frames.py ID
npx remotion render src/index.ts ID out/reel-final.mp4 --codec=h264 --video-bitrate=5M --audio-codec=aac --audio-bitrate=192k --concurrency=1 --port=3126
ffmpeg -v error -i out/reel-final.mp4 -f null -
ffmpeg -hide_banner -i out/reel-final.mp4 -af ebur128=peak=true -f null -
```

Смотреть out/check/ID/sheet.png, дополнительно середины анимаций, первые/последние кадры каждой компоновки. check-frames оценивает геометрию, а не смысл. Он должен завершиться кодом 0; ошибку исправить или обоснованно уточнить саму проверку, а не отключить её.

REVIEW.md: версии инструментов, исходник/хеш, список решений, что проверено визуально/инструментально/на слух, путь к MP4 и известные ограничения. MP4 без направляющих, редактируемый проект и все sidecar JSON сохраняются. Studio: npm run dev, затем точная композиция; открыть средствами среды. Не заменять ссылку на проект ссылкой на MP4.
